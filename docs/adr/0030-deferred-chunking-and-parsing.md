# 0030. 三项切块与解析能力：一项永久不做、三项暂缓

- 状态：已接受（2026-11-15）
- 取代：#33（语义断点 / 代码 AST / PDF 版面分析）、#55（非 markdown 版式还原）——两张票已关闭
- 相关：ADR-0012（切片原文与检索文本）、ADR-0015（词表与窗口）、ADR-0029（同一形态的负向决策）

## 背景

#33 与 #55 记了四项「明示不做」的能力，各自带翻案条件。它们作为待办票挂了一个月，期间几次被误读成"还没做"。2026-11-15 决定**关票**。

**关票不等于决策消失。** 票关掉之后内容仍可搜到，但没人会去搜一张关掉的票；而「我们决定不做 X」和「我们做了 Y」同样重要——前者能挡住一次重复讨论。所以把决策搬进 ADR，票里只留调查材料。

这四条的形态与 ADR-0029（砍图谱与编排）完全一致：**负向决策 + 写清理由 + 写清什么条件下翻案**。

---

## 决策一：语义断点切分 —— **永久不做**

按相邻段落的 embedding 相似度跌落点切，或让模型判断"这里换话题了"。

### 为什么是"永久"而不是"暂缓"

前三条理由都是成本问题，这一条是**结构问题**：

1. **我们的语料是 Markdown，标题本身就是结构。** 语义断点是为「无标题纯文本」设计的兜底（会议纪要、客服记录、转录稿）。在带标题的文档上切，它拿不到标题之外的任何信息。
2. **它引入一条不可验证的代码路径。** 断错位置**没有任何信号能报警**：不会抛错、不会降级、没有日志。切坏了只表现为"检索结果变差"，而检索结果的归因有五六种可能——**这种缺陷形态没法用测试守住**。
3. 它会与标题切分**竞争**：同一份文档既有 `heading_path` 又按语义断点切，交付单元的边界从此有两个来源，`section_id`（`sha256(文档 id : 标题路径)`）的定义随之失效。

第 2 条是决定性的：**我们砍图谱时用过同一个判据**（漏掉的边静默消失）。一条错了没人知道的路径，不该进主链。

### 翻案条件

出现「一份文档里大段内容没有标题」的真实案例**并且**该类文档占比不可忽略时——那时它切的是**另一类语料**，不与标题切分竞争，第 3 条理由不成立，可以重开。但**仍然要先解决"怎么发现它切错了"**：没有这个手段，重开也验证不了。

## 决策二：代码 AST 切分 —— 暂缓

按类 / 函数切，而不是按行或字符切。

当前只做了「超长代码块按字符窗口递归切 + 空行优先」，语言无关，足以保证长代码不被 embedding 截断。

### 翻案条件

接入代码仓库作为知识库时。**且必须同时做符号元数据**（`symbol` / `file_path` / `qualified_name`）——只按 AST 切、不建符号索引，检索照样定位不到「哪个函数」，等于白切。

## 决策三：PDF 版面分析 —— 暂缓（主导票 #55）

标题 / 正文 / 表格 / 页眉页脚的 bbox 识别 + 阅读顺序还原，处理双栏、跨页表格、页眉页脚去重。

这是**解析层**能力，不是切块层。当前 PDF 走"OCR 后按页拼 Markdown 标题"，本质是**猜结构**：把每页最高层级元素直接当标题。

### 已实测到的两处确定误判（#55 记录）

1. 每页第一个标题都被识别成 h1，跨页层级不延续（第 2 页的 h2「整机规格」变成 `#`，文档级父级丢失）；
2. 一句 10pt 正文被打成 `##` 标题，之后正文全挂到这句"标题"下。

### 为什么不修

评测语料 20 篇**全是 markdown**，PDF 结构还原的收益一次都没被量化；而修复要一组启发式阈值（长度上限、标点集、字号比、占比否决），每条都可能在新语料上翻车。

### 翻案条件

1. **前置**：先把评测语料扩到 PDF / TXT / HTML——**否则改了也无法证明改对**（与 ADR-0029 同一条纪律：没有能分辨的尺子，测量等于自欺）；
2. 有真实业务 PDF（尤其扫描件）进来，且确实需要"按章节检索"。

### 开工前不必重做的调研

`#55` 正文里保留：PDF fixture 与生成脚本（注意**必须用嵌入 TrueType 中文字体**）、两条钉住当前缺陷的 `test_known_limitation_*`、MarkItDown 0.1.9 的逐项实测结论（docx 与现有实现逐字节相同；pdf 部分比 pdf-inspector 差、不能换）、WeKnora 的引擎结构。

## 决策四：非 markdown 版式还原（docx 升格 / size 库溯源） —— 暂缓

已定的边界（**不是**本 ADR 要改的东西）保持不变：

| 库类型 | 白名单 | 切法 |
| --- | --- | --- |
| `structure` | 固定 `[markdown]`（传别的 422） | 结构化（标题 / 表格 / 代码 / 折叠 / 页码） |
| `size` | 默认五个全开 | 一律固定 size，**不产 `heading_path`** |

`size` 库没有 `heading_path` / `section_id`，因此折叠、页码、章节溯源都不生效——这是**写进文档的承诺边界**，不是缺陷。

### 翻案条件

与决策三同：先有跨格式评测语料，再谈 docx 转 md 升格通道与 size 库的轻量 section 抽取。

---

## 被否决的做法

| 做法 | 为什么不行 |
| --- | --- |
| 把四项做成"可配置开关"，默认关 | 默认关的能力会变成下一条死代码——第 11 步已经踩过两次（图谱注入位默认 `None`、编排预算默认 4 秒），两次都是"用例全绿、生产从不发生" |
| 让模型判断"该不该切"（LLM 断点） | 把一条**静默失败**的路径换成一条**要花调用**的静默失败路径，失败形态一模一样，还多了成本 |
| 直接删票、不留 ADR | 那就等于抹掉"我们考虑过并否决了"，下一个人会从零再讨论一遍 |

## 后果

- `#33` / `#55` 关闭，调查材料留在票里（可搜）；决策以本 ADR 为准。
- 四项**都不进**第 12 步及之后的主线排期。
- 语义断点切分**永久不做**：将来若要重开，先给出"怎么发现它切错了"的手段。
