# 12. 检索结果的可选装饰字段

日期：2026-11-09

## 状态

已接受

## 背景

第 4 步的检索契约（ADR-0010）规定请求体只接受 `kb_ids` / `query` / `mode` / `top_k`，
响应每条结果是「切片原文 + 排序分 + 出处」，且唯一键是 `(kb_id, chunk_id)`。

第 3 步增补把切块粒度变细（h3 成边界、表格按行产出）。粒度变细之后，单条结果
「找得准」但「喂不够」：一个 150 字的细片不足以让模型给出答案，一次检索还得再
发三五次请求才能补齐上下文。表格的行级片更极端——只给一行，模型看不到列含义。

于是引入三样**返回前**的装饰，都不新增存储、都不改召回：

| 字段 | 作用 | 默认 |
| --- | --- | --- |
| `parent` | 上下文恢复：按命中情况给整节或邻居窗口 | 开 |
| `table_context` | 命中行级表片时附带同组整表全文 | 开 |
| `page` / `doc_version` / `split_strategy` | 引用定位与跨库解释 | 恒返回 |

## 决策

### 1. 装饰字段属于响应，不属于请求契约

请求体增加 `include_parent` 与 `expand_table_rows` 两个**布尔开关**，不增加任何
调整检索行为的旋钮（`k` 仍写死、融合参数仍不可调，ADR-0010 的这条限制不变）。

新增的响应字段全部有默认值（`null` / `false`），旧调用方不解析它们也能正常工作。

### 2. 默认开，并接受响应体积变化

`include_parent` 与 `expand_table_rows` 默认 `true`。默认关着就等于这两项能力没做——
它们解决的正是「每次检索都要再发几次请求」的痛点。

**这会让旧调用方的响应变大**（父节可能带来数倍体积）。这是有意的：检索结果的价值
在于「能直接喂给模型」，而不是「最小字节数」。需要旧体积的调用方显式传两个 `false`，
此时响应体与改造前逐字一致（有测试钉住）。

### 3. `content` 永远是切片原文

表格展开**不得**替换 `content`。`content` 的契约是「切片在文档里的那段原文，被
引用、被回溯的也是它」（见 GLOSSARY）。整表全文放在独立的 `table_context` 里。

理由：一旦替换，引用就指不回原来那一片，而「这一条到底对应文档哪一段」是 RAG
能立住的前提。

### 4. 上下文恢复有两种粒度，不再只有「整节」

| 命中情况 | 返回 | 理由 |
| --- | --- | --- |
| 同节只命中 1 片 | 该片 + 前后各 1 片（`expansion=neighbors`） | 邻近片常补全被切断的句子 |
| 同节命中 ≥2 片 | 该节全部（`expansion=section`） | 命中多处说明答案跨了子节 |
| 跨 ≥2 个节 | 各节全部（`cross_section=true`） | 跨节题本来就需要多节上下文 |

一刀切返回整节会把 token 花在没命中的片上：命中 1 个 150 字细片却返回 1000 字整节，
是 7 倍浪费。GLOSSARY 的「上下文恢复」因此从「拼回父章节」放宽为「拼回所属章节，
粒度按命中情况分级」。

### 5. 唯一键 `(kb_id, chunk_id)` 必须贯穿到装饰查询

回查 `meta`、整表、同节切片时，键都用 `(kb_id, chunk_id)` 而不是单独的 `chunk_id`。
跨库同 ID 的两条结果必须能各自取到自己的 meta，不能被后到的那条覆盖。

### 6. 装饰查询同样要确定性

`fetch_table_chunks` 加 `ORDER BY`（文档、`table_part`、切片 ID）并取「首个胜出」，
且带 `index_version` 过滤（与召回口径一致）。否则哪张整表胜出取决于 PG 的行序，
违反 ADR-0010 的「同一份输入两次返回同一顺序」。

## 后果

- 旧调用方响应变大；需要旧体积时两个开关都传 `false`。
- 多一次按 ID 的 `meta` 批量查询（三样装饰共用这一次）。
- 装饰全部在返回前完成，**不需要重建索引**——索引侧的改动（h3 边界、行级表、
  节说明、型号段）才需要重建。
- `page` / `doc_version` 现在有字段可返，ADR-0005 的「检索结果每条带稿号」落地；
  稿号参与过滤仍留给版本生命周期那一步。

## 备选方案

- **把装饰塞进融合层的候选对象**：否决。融合层只该带对外字段，内部字段塞进去会
  顺着响应漏出来。
- **默认关、让调用方显式开**：否决。默认关的能力等于没做；这项改造的全部价值就是
  「一次请求拿到可用上下文」。
- **用 `content` 直接替换成整表**：否决。破坏引用可回溯性，见决策 3。
