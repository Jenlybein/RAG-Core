# 13. 一条检索结果代表一节，而不是一个切片

日期：2026-11-09

## 状态

已接受

## 背景

第 3 步把切块粒度变细（h3 成边界、表格按行产出），检索的「找得准」变好了，
但引入了两个新问题：

1. **一条结果喂不饱模型。** 145 字的细片刚好覆盖一个子节的一小段，模型要回答
   问题得再发三五次请求补齐上下文。
2. **名额被同节碎片占满。** `top_k=5` 里可能有 3 条来自同一节的不同片，
   真正该出现的另一节挤不进来。

ADR-0012 的解法是给结果**附加** `parent` 与 `table_context` 字段（不改结果本身）。
实测下来这只解决了一半：字段有了，但排序与名额分配仍按「片」进行，
第 2 个问题一点没好转。

## 决策

### 1. 折叠：用小片算分，用大块交付

检索仍按小片算分（保住「找得准」），**返回前把同一父节的命中折成一条**。

| 单元种类 | 归组键 | 内容 |
| --- | --- | --- |
| 表格 | `(文档, 章节, table_part)` | 整表全文 |
| 其余 | `(文档, parent_section_id)` | 父节全文（分级，见下） |

同一张表的多个行级片、同一父节的多个片，各只占一个名额。

### 2. 身份是 `section_id`，`chunk_id` 降级为代表片

一条结果代表一节，所以它的身份必须是节，不是片。新增 `section_id` 作为主标识，
`chunk_id` 保留为「让它浮上来的那一片」（组内分最高那片）。

**为什么不把多个 `chunk_id` 放进一个列表**：那会把内部索引结构漏进契约，
让调用方以为「一条结果 = 多个切片」，语义反而更糊。子片 id 另放
`source_chunk_ids`，只作溯源用，不是主键。

### 3. 内容内联返回

**不**返回节 id 让调用方或模型再去取一次。small-to-big 的全部价值就是省掉这次
往返；让模型去取等于把「两轮」变成「三轮」，比一开始就用大块更慢。

### 4. `score` = 单元内命中片的最高分

取 max，不取平均。平均会惩罚「一节里多片都命中」这种**好情况**：命中越多，
平均越低，方向是反的。

### 5. 分级：不是每次都返回整节

| 命中情况 | 给什么 | `expansion` |
| --- | --- | --- |
| 同一单元只命中 1 片 | 该片 + 前后各 1 片 | `neighbors` |
| 同一单元命中 ≥2 片 | 整节 | `parent` |
| 跨 ≥2 个单元 | 各节全文 | `parent` |
| 表格单元 | 整表 | `table` |

一刀切返回整节会把 token 花在没命中的片上：命中 1 个 150 字细片却返回 1000 字
整节，是 7 倍浪费。

### 6. over-fetch 补足条数

内部召回 `top_k × 3` 个候选，折叠后截断到 `top_k`。

**因子写成常量，不做成配置项**：15 道题的样本量下，任何可调旋钮都必然被调成
过拟合值。×3 的依据是实测每题平均 1.7 片同节命中，余量足够。

## 与 LangChain 参考实现的两处有意偏离

`ParentDocumentRetriever` / `MultiVectorRetriever` 是这套模式的参考实现。我们对齐
了它的主干（小片检索 → 按父 id 去重保序 → 批量取父内容 → 返回父内容），但有两处
**刻意不同**：

| 偏离 | 参考实现 | 我们 | 理由 |
| --- | --- | --- | --- |
| 去重后条数 | 不补足，可能只返回 1 条 | over-fetch 后截断到 `top_k` | `top_k` 是对外承诺，返回 1 条会让调用方困惑，评测的 R@k 也会失真 |
| 单元的分数 | `mget` 只返回文档，没有分 | 取组内最高分 | 我们的响应有 `score`，调用方会拿它做阈值判断，不能空着 |

两条都写进代码注释，避免后人以为是漏抄。

## 后果

- **破坏性变更**：`parent` 与 `table_context` 两个字段删除（折叠后 `content`
  已经是大的，它们是重复数据）。调用方若读这两个字段需改用 `content`。
- 响应体积变大：`top_k=5` 从 5×145 字变成最多 5×整节。要旧体积传
  `include_parent=false`，此时不折叠、逐字返回小片。
- 向量召回多取 3 倍候选；向量查询本身是对数级，延迟影响很小。
- **不需要重建索引**：折叠全在返回前完成。
- 评测必须同时报两个口径（`chunk 级` 与 `delivered 级`），否则「片变碎」与
  「返回单元变了」这两件事又会被混为一谈。

## 备选方案

- **继续用 ADR-0012 的附加字段**：否决。实测只解决了「喂不够」，没解决「名额被占满」。
- **按父节重新打分后再排**（邻居分数聚合）：否决。这是自造公式，没有参考实现；
  15 道题的样本量下，任何聚合权重都会被调成过拟合值。
- **在评测里复刻折叠逻辑**：否决。此前三次数字出错的根因都是「评测复刻生产逻辑
  但复刻错了」，所以折叠必须是纯函数，生产与评测共用一份实现。
