# 0029. 第 11 步收窄：不建轻量图谱、不出独立编排块，只做内部受控 Research

- 状态：已接受（2026-11-15）
- 取代：ADR-0027（节级图谱，已否决）、ADR-0010 第七次与第十次修订中关于编排的定位
- 相关：ADR-0001（只检索不生成）、ADR-0025（索引即构建产物）、ADR-0026（引用块）、ADR-0028（受控 Research）

## 背景

第 11 步原本要交付四件事：索引即构建产物、轻量图谱、切片编排、受控 Research。

四件都做完了、都有用例、都绿了，然后拿真环境跑了一轮对照。结果是**两件事应当撤销**：

- 图谱：做得对不对有数据，**值不值得**没有数据，而它的能力上限恰好落在最没价值的场景上；
- 编排：它给的是"结构"不是"更少材料"，代价是二十秒，而**对外没有消费者**。

撤销前的完整状态打了 tag `step11-with-graph-and-orchestration`。本 ADR 记录为什么撤、撤到什么程度、什么条件下可以重新考虑。

---

## 决策一：不建轻量图谱

### 先说清楚：不是因为"正则不可靠"

票面最初的担心是「正则匹配容易漏边」。**实测不支持这个理由**：

补上两条确定性定位规则（R1 标题名引用、R2 编号定位）之后，可确定性定位 **37 / 38 条**标注为"显式引用"的表达，上限 recall **0.974**；工程档 0.944、政策 `1.000`、纪要 `1.000`。上线后的实际测量是 precision **1.0000** / recall **0.8421**。

**正则这条路走得通。走不通的是它的价值。**

### 四条真实理由

| # | 理由 | 说明 |
| --- | --- | --- |
| 1 | **只覆盖「显式指路」** | 边只存在于作者写了「见 X 节」的地方。文档之间**大部分**有用的关联是隐式的（同一概念在两篇里用不同说法），正则一条都抓不到。所以这套图谱的能力上限，正落在它最没价值的场景上 |
| 2 | **价值未被证明** | 对照实验里注入 **0 条**——语料只有 3 篇 15 节，`top_k` 二十条的召回深度已经覆盖全库，没有"补"的空间。能证明它有用的实验条件（大语料 + 压低召回深度）我们还不具备 |
| 3 | **隐性维护成本** | 每来一种新文档写法就要加规则；**漏掉的边静默消失、不报错**；还要跟着索引版本一起重建。这是一笔持续支出，换来的是未证明的收益 |
| 4 | **可被替代** | 跨文档漏召回由 Research 的定向补证覆盖（见决策三）；"作者明确指路"本身是低频场景 |

### 一句话

> 图谱解决的是"**相似度找不到、但作者写了**"的那部分材料。这部分材料在真实文档里是少数，而且它恰好是**最容易被其他手段覆盖**的少数。

## 决策二：不出独立的编排块

### 被测量支持的四个数字

| 读数 | 值 | 意味着 |
| --- | --- | --- |
| 材料条数与字数变化 | **0** | 它不让材料变少，只是给材料贴标签 |
| 每题延迟 | 0.22 秒 → **22.5 秒**（p50） | 两个数量级 |
| 每次模型调用 | 0 → **2 次** | 两次串行结构化调用 |
| 没有任何要点引用的材料 | **15% / 23%**（两个题集） | 它标了价，但没人能判断标得对不对 |

还有一条事故性证据：整步预算默认写 4 秒（两次调用共用），而单次调用实测 4.5–25 秒，于是**生产默认配置 20/20 全部降级、一块都产不出**，每题还白付 4.2 秒。所有用例都绿——因为用例自己传了 `timeout_ms`，**没有一条走默认值**。

### 撤销的真正理由：对外没有消费者

调用方要的是**材料**或**答案**。"要点 + 角色"这个中间结构没有下游：它既不能直接回答，也不能直接引用。

而它占的是**别人的模型调用时间**：`/rag/retrieve` 承诺几百毫秒返回材料，一个可选项把这条承诺拉到二十秒以上。

### 保留下来的两样东西

这两样是原模块里唯一真正有价值的部分，**搬进 Research**：

1. **「模型只点序号、正文回库重建」** —— 模型的输出里没有可装正文的通道，提示词注入最多让它点错序号（后果是一条真实材料站错位置），而不是注入一段凭空生成的内容。这是结构性防护，与"是否对外"无关。
2. **`coverage` 这个概念** —— 搬进 Research 的输出，作为 `gaps`：它不再是"完整度自评"，而是"答案为什么不完整"的解释。

## 决策三：Research 的分解必须独立于材料

**这是整套设计成立的前提，也是这次收窄里唯一真正新的技术结论。**

### 那个盲区是怎么来的

编排的完整度字段 `complete` 的定义是「我列的每个要点都有核心片撑住」。而**要点是从材料里归纳出来的**。于是：

```text
材料里没有的东西 → 归纳不出来 → 不会进要点 → 不会缺核心片 → complete 恒为真
```

这不是模型的能力问题，是**输出空间里根本没有"没有"这个选项**。

实测里它真的发生过一次：某题答案需要「银卡及以上 500 元上限」，而那一节（`points_policy:2.2`）根本没被召回——`complete` 仍然是 true。

> ⚠️ **样本量 1，不要把这个案例当成"发生率"。** 能说的是：它在原理上无法发现材料缺口（构造性成立），以及它至少真的发生过一次。

### 修法：把基准从材料搬到问题

```text
问题 → 分解成 P1…Pn（输入里没有材料）
     → 对每个 Pi 问"材料里有支撑它的吗"
     → "没有"成为一个**可表达、可传递**的输出（gap）
     → 有 gap 才补检索，补完仍没有就写进 gaps 并让答案声明不足
```

**分解的输入里绝不能有材料。** 一旦给了材料，模型就会按"材料支持什么"来写要点——那就退回原点。这一条要写成用例钉住：喂材料进去必须红。

## Research 的流水线

```text
① 分解（1 次调用，输入只有问题）
   → P1…Pn（≤5 条；「每条 ≤30 字」是提示词里的软约束）+ **每个 Pi 各一条**检索查询（计划层 1:1，见下）
② 初召回（0 次模型调用）→ pool0
③ 覆盖判定（1 次调用）
   输入：P1…Pn + pool0 每条材料的「标题 + 正文摘录」（单条不设上限，总预算 12000 字）
   输出：每个 Pi → 支撑它的材料序号，或 none（只输出序号，正文回库重建）
④ 定向补证（0 次模型调用）→ 只对 none 的 Pi 补检索，≤2 条
⑤ 复查（1 次调用，仅当 ④ 发生过）→ 重跑 ③
⑥ 生成（1 次调用）→ 答案带引用；仍有 gap 必须声明材料不足
```

### 四条闸门

| 闸门 | 内容 | 为什么必须有 |
| --- | --- | --- |
| **引用闸** | 答案里每个事实必须能指到某个证据编号 | 已有（ADR-0026 的四条硬校验） |
| **缺口闸** | 存在 gap 时答案必须声明不足，**不许用模型自身知识补** | 上下文不足时模型仍有 35–62% 概率"答对"，反面就是 38–65% 概率"看起来答对了其实在编"。没有这道闸，覆盖判定等于白做 |
| **预算闸** | ≤4 次模型调用（实施值 **3**：分解 + 判定 + 生成）、≤6 次检索（实施值 **5** = 首轮 3 + 补证 2）、90 秒阶段预算 | 它是可选能力，不能把请求拖成作业 |
| **定义闸** | 「支撑」= 材料里能**直接读出**该事实，不是"相关" | 不写死，模型会把"相关"当"支撑"，覆盖率又变乐观 |

### `/rag/retrieve` 的定位不变

毫秒级、不调模型、不编排、不注入图。它只负责"把材料取回来并折成交付单元"，其余全部搬到 Research。

## 被否决的做法

| 做法 | 为什么不行 |
| --- | --- |
| 让 LLM 提图谱候选（替代正则） | 重建两次会得到不同边集，可复现性没了；且换来的增量在实测里是 0 条（那一层缺口是语法不是语义） |
| 把编排设成默认档位 | 二十秒的默认延迟会推翻 `/rag/retrieve` 的毫秒承诺 |
| 分解时先给模型看材料目录 | 能减少"分解出库里没有的东西"，但会把基准重新拉向材料侧。**若要试，必须先用标注集证明它不会让 gap 消失** |
| 拆成"一次调用出要点+角色"以省一半延迟 | 会让模型顺手给完整度自评，而完整度必须由材料数出来，不能采信自评 |
| 保留图谱代码但不接线 | 会变成下一个「默认 `None`、生产永不发生」的死代码——这一轮已经踩过一次 |

---

## 翻案条件

**图谱**（四条同时满足才重新考虑）：

1. 语料足够大，且召回深度压低到"相似度真的会漏"；
2. 有一批**只靠显式引用才能找到**的材料，且证明它对答案有影响；
3. 隐式关联有别的办法处理（否则上限还是那条线）；
4. 有人愿意承担"每来一种写法加一条规则"的持续成本。

**编排**：

1. 出现真实需求："我要结构化材料但不要答案"；
2. 且能把两次调用压到一次、延迟压到 5 秒内——**否则它应该留在 Research 内部**，因为 Research 本来就在做"要点 + 材料"这件事。

## 实施备注（#164 落地后，2026-11-15）

本节记下四处**原文没写清或写矛盾**的地方，以及实施时怎么定的。改的是解释，不是决策。

### 1. 计划层 1:1 与执行层截断是两件事

原流水线写「每个 Pi 一条查询」，预算闸又写「≤6 次检索」，两处一起读会得出「N 条要点就查 N 路」——
而 N 最多 5、加上补证 3 就是 8，永远超预算。实施取法：

- **计划层强制 1:1**：每个要点必须配一条查询，配不出来就整份计划不成立（退回原问题查一次），
  而不是补一条空查询（会造出**假缺口**）或删掉这个要点（会造出**假完备**）；
- **执行层截断到 3**：首轮只跑前 3 条查询；
- **没跑到的要点照样进判定**，它们大概率是 `none`，于是走 ④ 用**自己的那条查询**定向补 ——
  这正是"计划层 1:1"的价值：**补证用的查询早就在计划里备好了**。

总检索数因此是 3 + 2 = **5 ≤ 6**，与预算闸一致。

### 2. 没做 ⑤ 复查（补证后再判一次）

原文流水线有 ⑤，实施**没有做**。原因与代价都记在这里：

- 做了就是 4 次模型调用（+兜底 5），顶到 ADR-0026 §5 的硬顶；
- 代价：补证捞到新材料的要点，状态记 **`unknown`**（"材料到了、但没人再回答过它支不支持"），
  不是 `supported`（乐观），也不是 `none`（会让缺口闸把一份其实有材料的答案判死）；
- **`unknown` 不进 `gaps`**：不知道的时候既不该声明"材料不足"，也不该假装有支撑。

**加不加 ⑤ 的判据**（先测再定，别凭感觉加成本）：跑一批题，统计
「补证发生过、且至少一个要点落在 `unknown`」的比例。这个比例高到影响答案质量，再加 ⑤ 并把
ADR-0026 §5 的硬顶一起改；否则它就是"多一次调用换一个更漂亮的字段"。

### 3. 判定词表是 `supported` / `none` / `unknown`，没有 `partial`

原票面写「status 只有 `supported` / `partial` / `gap`」，实施落成三个词、但**不是这三个**：

- 逐要点的语义只有三种：读得出来（`supported`）、读不出来（`none`）、没判过（`unknown`）。
  **一个要点不存在"部分支撑"**——"部分"是整体层面的量，属于 `evidence_state` 的
  `partial`，不是单个要点的状态；
- `none` 沿用判定输出里的同一个词，读判定记录与读响应时看到的是同一套词；
- 缺口清单仍叫 `gaps`，只收 `none`。

### 4. 缺口闸是文本级的

现在要求「`gaps` 非空 ⇒ 渲染串里必须出现 `材料不足`」，不要求「每个缺口要点各自一块
`insufficient`」。收紧要成立，得把要点编号暴露给生成步——那等于**扩大模型的可表达面**，
而这一轮的整个方向是收窄它。**这条闸挡的是"假装没缺口"，不是"逐条对齐缺口"**；后者留给
`coverage.points` 让调用方自己看。

### 5. 响应多一个 `coverage` 顶层键

`{"points": [{"point_id", "status", "evidence_ids"}], "gaps": [要点编号]}`，HTTP 与 MCP 走同一处装填。`point_id` 与计划清单（`A1…An`）对得上；`evidence_ids` 是「哪几片撑住了这个要点」的直接证据，判定给的就是它。
它是 Research **内部**字段，不做独立接口——孤立地给一坨"要点 + 角色"没有下游，这正是编排块
被撤销的理由；但作为"答案为什么不完整"的解释，它有用。

`/rag/retrieve` 一个字节没动。

### 6. 判定输入给的是正文摘录，不是「摘要」

ADR 正文那一步原本写「标题 + 摘要（≤200 字）」，实施给的是**标题 + 正文摘录**（单条不设上限，
总预算 12000 字）。改文档不改代码，理由：

- 判定要回答的是「材料里能不能**直接读出**这个事实」——摘要可能恰好把那关键一句摘掉，
  于是一个其实有支撑的要点被判成缺口（**假缺口**，比假完备更容易被发现，但一样是错）；
- 成本已经由总预算限住，单条上限没有额外收益。

同理，「要点每条 ≤30 字」是**提示词里的软约束**，代码不截断：截断会改掉要点本身的意思，
而要点是覆盖判定的基准。这两处的取法一致——**能用软约束表意的，不要用硬截断打断语义**。
