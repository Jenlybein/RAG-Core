# 0026. 受控 Research 可以生成引用块：ADR-0001 的唯一例外，且只开一道口

- 状态：已采纳（第 11 步 · C 票）；**本文显式收窄 ADR-0001 的适用范围，不改写它**
- 日期：2026-11-13
- 相关：父 spec #138、票 #139（本文）、**ADR-0001「中台不生成答案，接口是 retrieve 不是 chat」**（本文收窄它的适用范围）、ADR-0007 / ADR-0008（错误契约）、ADR-0010（检索契约：`/rag/retrieve` 不变）、ADR-0018（三层授权：Research 的开关与配额按层分）、ADR-0021（观测旁路：一次 Research 一份 trace）、**ADR-0028「检索内核只抽检索内核本身」**、`GLOSSARY.md`「受控 Research」「引用块」「停止原因」「生成答案」「切片编排」「引用回溯率」、`app/services/`（Research 服务，随 C 票落地）

## 背景

ADR-0001 写的是一条硬边界：中台对外的唯一业务动作是 `/rag/retrieve`，**不生成答案**。理由两条——职责重叠（租户本来就有问答逻辑）、契约扩张（一旦生成，`system_prompt` / `temperature` / 多轮历史会长出来）。

第 11 步要做的是「一次检索答不全时承认，并且定向补一次」。这条链路里有一步无法回避地要**产出判断**：这块材料支持这个要点吗？支持到什么程度？全都不支持时，该说「材料不足」还是「根本没有材料」？

三种做法摆在桌上：

1. **完全不生成**，把材料原样交回去，判断留给调用方；
2. **放开发挥**，让模型写答案；
3. **允许生成，但只生成「引用块」，且任何一块不过校验就整单不生成**。

## 决策

### 1. 收窄的是接口，不是「中台可以生成答案」

从本文起，ADR-0001 那句「中台不生成答案」按**接口**读：

| 出口 | 能否生成 |
| --- | --- |
| `POST /api/v1/rag/retrieve` | **永不生成**（ADR-0001 原文不动，响应逐字节不变） |
| MCP 工具 `rag_retrieve` | **永不生成** |
| `POST /api/v1/rag/research`、MCP 工具 `rag_research` | 可以生成，**只生成引用块** |

- **它不是任何档位的一部分**：`speed` / `balanced` / `quality` / `custom` 都不含 Research。Research 只由「这套集成有没有 Research 授权」与独立配额决定，按次选择，不是按 Key 固定。
- **两个入口共用同一份实现**：HTTP 与 MCP 只递参数，行为必须一致（ADR-0008 的同一形状）。
- **拒绝是明确的**：没有授权 → `FEATURE_NOT_ALLOWED`（20013），不静默降级成普通检索。静默降级会让调用方以为自己在用 Research，实际只是拿到一份材料。

### 2. 只生成「引用块」，不生成「答案」

**引用块 = 文本 + 证据下标 + 状态**：

| 字段 | 含义 |
| --- | --- |
| 文本 | 针对某个要点的一句话，长度与形状由后端约束，不是自由写作 |
| 证据下标 | 候选池下标按最终材料顺序分配（`E1`、`E2`…），**模型只点，不造** |
| 状态 | `supported`（有核心片支撑）/ `insufficient`（材料不足，明确说不确定） |

**顶层 `answer` 只是渲染串**：它由引用块按顺序拼出来，不是第二种产物，也没有自己独立的内容。这一条很要紧——如果 `answer` 能有独立内容，校验就要做两遍，而模型写 `answer` 的那一遍**没有任何下标可核**。

`E` 编号的稳定性是契约的一部分：编号按要点顺序分配，同一次调用内不复用、不重排，调用方可以在自己的答复里直接引用「E3」。

### 3. 四条硬校验，任一不过 → `answer = null`

- **有结论的块必须至少引用一条核心片**：只引辅助片就下结论不成立；
- **材料不足的块不许伪造引用**：`insufficient` 的块不许挂下标；
- **答案里不许出现内部切片标识**：`chunk_id` / `section_id` 这类内部结构不许漏进对外文本；
- **文档之间冲突时分别保留来源、不替用户裁决**：两块并列、各自带来源，不给一句「综合来看」。

**不过就 `answer = null`，材料照给。** 这不是失败：材料（检索结果形状）+ 查询计划 + 轮次计数 + 停止原因仍然完整返回，调用方可以自己组织答复。把「不生成」做成一次仍有产出的返回，是这条接口在质量不稳时的默认落点。

**`stop_reason = degraded` 不蕴含 `answer = null`。** 两者是不同维度的事实：`stop_reason` 说「为什么停在这里」（例如规划或判断那一步降级了），`answer` 说「这一次有没有可发的结论」。降级出口之后状态机仍然走第 ⑤ 步：材料够、四条硬校验过得去，就照常产出引用块；把这两个字段写成同一条规则，会让一次本来能答的调用被统计成「什么都没答出来」。反过来也不成立——`answer = null` 可以发生在任何停止原因下（生成失败、硬校验不过、根本没有材料）。

### 4. 正文回库，模型只能点下标

模型只允许返回「要点 + 候选序号」。正文由后端按序号回查库里的原文重建，并逐条校验租户 / 库 / 版本全部匹配。**不信模型返回的文本**——这条一次挡住两类问题：提示词注入往答案里塞内容，以及模型复述时悄悄改写原文（改写后的「原文」就不再可回溯了）。

### 5. 成本显式，不藏在默认路径上

一次 Research ≈ 30 秒、3 次模型调用（Planner / Decider / Finalizer），比普通检索贵一个量级。因此：独立接口、独立配额（`research_qps` / `research_daily`，套餐与密钥配置两层同记）、响应里回显耗时与模型调用次数、MCP 工具描述写明「约 30 秒、有额外模型成本、普通问题先用 `rag_retrieve`」。

**模型调用的硬顶是 3，只有一条路径允许第 4 次**（#149 之后写死在代码里）：规划 / 判断 / 生成各一次 = `MAX_MODEL_CALLS = 3`；唯一例外是**生成阶段的强模型失败**（强模型未装配、调用失败或超时）换快模型重试一次，此时才触及含兜底位的 `MAX_MODEL_CALLS_WITH_FALLBACK = 4`（`app/services/research_limits.py`）。第 5 次在任何路径上都不成立——兜底占的是一个**单独的格子**，不是把 3 悄悄放宽成 4。别处引用这个数时一律引常量，不要写「3 或 4」这种二选一的句子。

不把这些写清楚，它一定被当成普通检索调用——然后账单与延迟由别人来发现。

## 被否掉的方案

| 方案 | 为何不选 |
| --- | --- |
| **完全不生成**：只给材料，判断留给调用方 | Finalizer 与**切片编排**重复。切片编排已经把候选整理成「要点 → 核心 / 辅助 → 完整度」，如果 Finalizer 连「这块材料支不支持这个要点」都不产出，五步状态机的最后一步就只是把材料再组织一遍——同一个判断做两遍，而两次可能给出两种结论（编排说 `complete`，调用方看材料觉得不够）。更具体的损失是：**`insufficient` 这个状态无处表达**。纯材料没有任何形状能说「这里我们确实没有材料，别硬答」，而「承认不足」恰恰是这一轮最要紧的产出之一。 |
| 让 `/rag/retrieve` 也带一个可选 `answer` 字段 | 一旦默认接口能生成，所有调用方都会打开它——那正是 ADR-0001 拒绝的形状（`/chat` 吃掉 `/retrieve`）。配额、评测、责任归属全要跟着改：一次检索的价格从「零模型成本」变成「一次大模型调用」。 |
| 先自由生成、再由后端回溯校验引用 | 校验不过就整块丢，返工率高；而且自由文本里没有结构化下标，回溯只能靠字符串匹配，误配比「点下标」高一个量级（同义复述、合并两句、换措辞都会让匹配失败）。这等于把「可回溯」押在字符串运气上。 |
| 让 Finalizer 直接输出最终答案（多段 / 可流式 / 可多轮） | 那是应用。多轮意味着会话记忆与上下文管理，流式意味着首字延迟成为契约——两件都要各自一个 ADR，且都不是检索中台该承担的（ADR-0020 已经就流式做过一次同类判断）。 |
| 把 Research 做成一个档位（`quality` 或第五档） | 档位是「这套集成平时用多好」，随 Key 固定；Research 是「这一次要不要多花 30 秒和 3 次模型调用」，按次决定、成本高一个量级。塞进档位等于让某些 Key 的每次调用都变贵，而调用方无法为单次收窄——这正是 ADR-0018「请求不进质量参数」要避免的反面。 |

## 影响范围

- **ADR-0001 的读法变了，字面没变**：读 ADR-0001 要连着读本文。术语表「生成答案」条随之限定：中台仍不生成「给终端用户的回答」，只产出可回溯的引用块。
- **新增一条数据面接口与第三个 MCP 工具**：`/rag/research` 只吃 `kb_ids` + `query`，不接受档位、条数、轮次任何参数（ADR-0018 的请求层规则不破）。响应不返回内部候选池全文，轮次只给计数。
- **`/rag/retrieve` 一个字节不变**（编排与图谱关闭时），黄金哈希用例守着。
- **两条独立配额列**（套餐与密钥配置各一），free / standard 为 0（等同关闭），专业版 1 QPS / 100 次每天；被拒的请求不扣额度。
- **身份与记账**：一次 Research = 一个 `log_id` / `trace_id` = **一行**归属索引（`chunk_ids` 存最终证据的节）；子检索不写归属索引（ADR-0028 给了这条的边界）。
- **责任边界变细**：答错了要能分开——引用块选错了片（检索侧）、要点分错了（组织侧）、Finalizer 点错了下标（生成侧）。三条各有各的日志与指标。
- **评测口径多一条**：「引用回溯率」——每一条引用能不能还原到库里原文。它只量可回溯，不量答得好。

## 翻案条件

- **Research 被当成普通问答接口用**（某租户的 `rag_research` 调用量远超 `rag_retrieve`，且 `stop_reason` 多是 `evidence_complete`）：说明「只给引用块」的约束没起作用。先收紧（连渲染串也去掉，只给引用块），而不是再加一层提示词约束。
- **出现第二条需要生成的出口**（例如「摘要」接口）：那说明这条边界判错了，**先回来改本文**，不要就地再开一道口。两道口之后，「为什么这个能生成、那个不能」就没有判据了。
- **生成质量成为验收项**（要评「答得好不好」）：那需要模型裁判与一套评测集，进的是旁证指标那一档（只提示、不阻断）；但四条硬校验不许放宽——它们是结构校验，不是质量评分。

## 自检

1. **谁可以生成？** —— 只有 `/rag/research`（HTTP 与 MCP 同一实现），且只生成引用块。
2. **为什么这条口非开不可？** —— 不开就无法表达 `insufficient`，Finalizer 与切片编排重复。
3. **生成失败时调用方拿到什么？** —— `answer = null` + 完整材料 + 查询计划 + 停止原因。
4. **ADR-0001 还有效吗？** —— 有效，范围收窄到 `/rag/retrieve` 与 `rag_retrieve`。
