# 0019. 明文 API Key 进浏览器：面板可读回原文，但默认不显示

- 状态：已采纳（**本期口径**，生产前与 ADR-0004 一起复审）
- 日期：2026-11-10
- 相关：`docs/adr/0004-plaintext-key-storage.md`、`GLOSSARY.md`「API Key」「调试台」

## 背景

ADR-0004 已经为「面板要能读到 Key 原文」做了决定：`api_keys.key_value` 存明文，理由是**调试台必须拿用户自己那把 Key 去打真实检索接口**，走完整六道关（鉴权、白名单、套餐、档位、限流、配额）。只存哈希的话，Key 生成后没抄下来就再也取不回来，调试台废掉一半。

但那张 ADR 只解决了「**后端能不能读**」。第 8 步要解决的是另一个问题：**原文要不要穿过网络送到浏览器**。这两件事代价不同——后端读库只暴露给能读库的人，浏览器拿到原文则暴露给页面上任何一段能执行的代码。

## 决策

`GET /console/keys` 返回 `key_value` 明文，并同时返回 `key_masked`（形如 `rc_live_…9f2c`）。前端遵守三条纪律：

1. **默认只显示 masked**；要明文必须点「显示原文」并二次确认。
2. **只进内存**：不写 `localStorage` / `sessionStorage` / URL / 页面标题。
3. **审计不记明文**：`GET /console/audit-logs` 是管理员**跨租户**可见的，把明文写进审计等于让管理员绕过「进不了用户面板」拿到所有租户的可用 Key。列表接口发明文，审计只存 masked。

## 后果

### 正面

- 调试台「选一把 Key → 打真实接口」成立，开发者看到的是线上真实链路而不是模拟；超配额/被限流时调试失败是**真实结论**。
- 与 ADR-0004 一致：一套取舍，不出现「后端存明文、前端却拿不到」的悬空状态。
- 审计里的 masked 形态既留痕又不扩大泄露面。

### 代价

- **任何能在这个页面上执行代码的东西**（XSS、恶意浏览器扩展、被污染的依赖）都能一次拿到该租户**全部** Key。这是必须写进风险清单的一条。
- 内网 http 环境下，Key 在传输层对同网段可见（与后端部署形态相关，不在本 ADR 的处置范围）。
- 「显示原文」这个按钮本身就是一次社会化工程：要让人明白它高风险，又不能让人因为麻烦而绕开调试台。

## 备选方案

| 方案 | 为何不选（本期） |
| --- | --- |
| 服务端中继：`POST /console/debug/retrieve`（收 `key_id`，服务端解出 Key 再调 `gated_retrieve`） | 更安全（Key 不出服务端），六道关也不会丢（限流/配额都在 `retrieval_gate` 里）。代价是新增一条入口，且调试台**不再经过真实 HTTP 路径**——它学不到「配额把这次调用打断了」这件事，而那正是这一章要教的。 |
| 页面不自带 Key，让用户自己粘贴（像 Postman） | 零暴露，但把「选一把 Key」退化成手工活，且贴错的 Key 会让人以为是代码问题。 |
| 只存哈希 + 创建时显示一次 | ADR-0004 已否决：面板刷新即失效，调试台同样受影响。 |
| 加密存库（哈希 + 密文双列） | 这是**生产**的正确解（ADR-0004 的后续方向），本期不做是因为多一层密钥管理会把重点冲淡。 |

## 后续修订的触发条件

生产化时必须同时处理三件事：Key 改「哈希 + 密文」双列（读路径从哈希列、展示从密文列）、面板的「显示原文」改为走一次性的短时令牌、以及 `GET /console/keys` 不再返回全量明文而是返回引用。到那时本文的决策 1、2 仍然成立（masked-by-default 与只进内存），被替换的只有「明文直接下发」这一条。
