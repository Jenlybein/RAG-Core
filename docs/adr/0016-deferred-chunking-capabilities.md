# 0016. 本阶段明确不做的四项切块能力

- 状态：已采纳（暂缓决策的记录，不是待办）
- 日期：2026-11-09
- 相关：ADR-0014「切块策略即语料准入」、ADR-0015「token 窗口」、issue #33 / #55

## 一句话

语义断点切分、代码 AST 切分、PDF 版面分析、以及非 markdown 格式的 md 结构化，**本阶段一律不做**。它们不是「不重要」，而是**当前语料与当前阶段没有验证手段**：评测语料 21 篇全是 markdown，做了也拿不到可对比的基线，等于凭空多一条没人测的代码路径。

把理由落档，是为了两件事：不被遗忘，也不被误以为已经做了。

## 三项与各自的翻案条件

### 1. 语义断点切分

按相邻段落 embedding 相似度跌落点切，或让模型判断「这里换话题了」。

- **为什么不做**：这是「无标题纯文本」的兜底方案（会议纪要、客服记录、转录稿、长聊天记录）。本仓库语料是 Markdown，标题本身就是结构，语义断点拿不到额外信息。
- **什么条件下再做**：真的接入转录稿 / 聊天记录类文档，或出现「一份文档里大段内容没有标题」的真实案例。

### 2. 代码 AST 切分

按类 / 函数切，而不是按行或按窗口切。

- **为什么不做**：语料里没有代码库，也没有「代码问答」场景。当前只做「超长代码块按窗口递归切 + 空行优先」，语言无关，足以保证长代码不被 embedding 截断。
- **什么条件下再做**：接入代码仓库作为知识库时。届时要同时解决「按符号名建元数据」（`symbol` / `file_path` / `qualified_name`），否则按 AST 切完仍然检索不到。

### 3. PDF 版面分析

标题 / 正文 / 表格 / 页眉页脚的 bounding box 识别 + 阅读顺序还原，处理双栏、跨页表格、页眉页脚去重。

- **为什么不做**：本轮真的验证过 `pdf-inspector` 能给出 h1/h2（按字号）与管道表格，端到端也能切出正确的 `heading_path` 与页码；但查出两处**确定的版式误判**：每页第一个标题都被识别成 h1、跨页层级不延续（第 2 页的 h2 变成 `#`）；一句 10pt 正文被打成 `##` 标题，之后正文全挂到这句「标题」下。
- 修复需要一组启发式阈值（长度上限、标点集、字号比、占比否决），每条都可能在新语料上翻车；而语料全是 markdown，收益一次都没被量化。
- **什么条件下再做**：评测语料里出现真实 PDF，且能给出「修复版 vs 现状」的量化对照。

## 与语料准入的边界（已落地，不是本票范围）

`structure` 库固定只收 markdown（格式不匹配当场 422），`size` 库默认收全部格式但不产 `heading_path`。`split_strategy` 建库必填、无默认值，`allowed_formats` 是独立列，一致性在应用层校验——见 ADR-0014。

也就是说：**非 markdown 格式目前根本进不了结构化切块链路**，PDF / docx 版式还原的收益没有落点。这是「不做」的结构性理由，不只是优先级。

## 翻案纪律

任何一项要做，先出新的 ADR，并满足两条：

1. 有能暴露该项收益的**真实语料**（不是合成 markdown）；
2. 有同语料、同题、同判据的「现状 vs 修复」对照数字。

没有数字不动手。
