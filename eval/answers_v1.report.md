## 七、口径与已知偏差

1. **选 50 题 vs「12 题型各 2~3 题」**：排除 `absent` 后剩 11 个可答题型，11×3=33 < 50，两者在算术上不能同时成立。本报告采用**下限口径**：每个题型至少 2 题，余量按池子大小用最大余数法分配，总量凑满 50。想要严格 2~3 就用 `--per-type-max 3`，脚本会把「最多 33 题」的差额显式报警。
2. **`absent` 被排除**：那 6 道题在库里本就没有答案，喂给生成模型只会逼它编，与「答案只依据标注切片」直接冲突。它们仍在门禁里按误召口径评估（#107）。
3. **`false_premise` 限量纳入**：提示词里单独要求「前提不成立」时明说，这类题的答案格式与其它题型不同，混在通过率里读的时候要留神。
4. **只喂标注切片**：正文由离线真实切块器产出，切片经 `scripts/eval_retrieval._resolve_question_labels` 解析（0 片即失败），不连 PG / ES / 嵌入；产物里只留溯源坐标，正文可由「语料版本 + 坐标」复原。
5. **机械校验的边界**：归一化只抹平四处差异——全半角、空白、千分位、中文数字（「三天」＝「3 天」）；后缀（`Pro`）、位数、前导零一律照原样比。它查的是「数字 / 型号 / 错误码 / 编号能不能在正文里找到」，查不出「用词不同但意思对」，也查不出「把两片的内容张冠李戴」。它挡的是**编造**，不是语义错误——语义那一关仍要靠抽检与后续的 LLM 裁判。
