# 图谱引用边的标注集（#158）

这份目录回答一个问题：**生产抽取器（`app/services/section_graph.py`）在「不是我们自己写的」文档上，
precision / recall 是多少？**

`eval/corpus-refs/`（票 A3）回答不了这个问题：那三篇语料与抽取器出自同一份设计文档，9/9 全绿只
证明「我们自己写的那三种写法被认出来了」。所以要有一份**独立标注的测量集**，以及一个只算数的
测量脚本。

- 标注：`labels.json`（87 条，三档语料，四类标签）
- 报告：`report.md`（由 `scripts/eval_graph_labels.py --write` 生成，**不要手改**）
- 语料：`corpus/policy/`、`corpus/minutes/`（合成的两档）；工程档直接用本仓库 `docs/adr/` 的真实文档

## 一、什么算「引用」，什么只是「提到」

判据只看**读者要办成这一节的事，需不需要真的去读目标那一节**，不看句子里有没有「见 / 参见 / 详见」
这几个字（有字不一定依赖，没字也可能依赖）。

| 标签 | 判据 | 例子 |
| --- | --- | --- |
| `explicit` | 句子的作用就是**指路**：读者不读目标节就答不出本节的问题；且目标能**唯一**定位到本语料里的某一节 | `（ADR-0025 决策五）`、`见背景四条`、`按《会员权益与积分细则》第 2 条执行`、`[退款流程](#第二节-退款流程)` |
| `ambiguous` | 看得出指向某处，但**落不到唯一一节**：整篇引用、裸节号/裸条号、范围引用（「决策 1–6」）、附件（「见附件 A」）、目标不在库（「以采购合同为准」）、定位符与括注自相矛盾 | `见第 3 条`、`以《X》为准`、`（ADR-0025）`、`[ADR-0025](0025-….md)`（无节号） |
| `implicit` | **指代型**：只有相对指示语（「见上周那份」「按上次说的」「见下」「上面第 2 条」），句子里没有任何可解析的定位符——正则没有输入可用 | `见上周那份纪要`、`按上次分工来` |
| `noise` | 提到但不依赖：**格式示例**（把「参见《X》第 N 节」当成语法例子引在「」里）、**否定/废弃语境**（已废止 / 已取代 / 已关闭 / 不再追踪）、转述别人文档里怎么写 | `「参见《X》第 2.4 节」「本文件第三节」`、`原《优惠券使用细则》第 2 条已废止` |

**「提到」与「依赖」的分界线**，三句话：

1. 把目标节删掉，本节还能不能照原样用？能 → 只是提到（`noise`）。
2. 目标能不能落成**唯一一节**？不能 → 弃权（`ambiguous`），不是「漏」。
3. 句子里有没有定位符？没有 → `implicit`。这三类的差别不是程度，是**成因**（所以分母也不同）。

「整篇链接」为什么算弃权而不是真边：图的节点是节（ADR-0027 决策 1）。「整篇」对应哪一节，作者
没说、也没有唯一解——ADR-0027 决策 3 的原话就是「目标存在歧义时不建边」。而如果文档恰好只有
一个顶层节，代码会把它解到那一节（ADR 的 h1 元信息块），那是一条**粒度错的假引用**，计入
precision 的误报。

## 二、四类标签怎么影响两个数

| 标签类 | 进 recall 分母 | 上面建出边算 |
| --- | --- | --- |
| `explicit` | 是 | 命中（TP） |
| `ambiguous` / `implicit` / `noise` | 否 | 误报（FP） |

`recall` 的分母**只放 `explicit`**：三者都是「按设计不该有边」，把它们塞进分母会让 recall 变成
「抽取器有没有猜对人类的沉默」。同理 `precision` 的分母是**全部建出来的引用边**——包括在
`noise` 语境里建出来的，因为那正是会以假引用形式出现在回答里的东西。

## 三、形态细分（票面六类 + `other` 的细分）

`form` 是票面要求的那六类：`title_section`（`《X》第 N 节`）、`same_doc`（`本文件第 N 节`）、
`markdown_link`、`anchor`、`chinese_ordinal`（中文序数）、`other`。真实文档里 `other` 吃掉
一大半，所以每条还带一个 `form_detail`，报告按它展开：

| `form_detail` | 形态 | 出现在 |
| --- | --- | --- |
| `adr_decision` | `ADR-00NN 决策五`（文档编号 + 决策序号） | 工程档 |
| `adr_quoted_heading` | `ADR-00NN「节标题」` | 工程档 |
| `same_doc_decision` | `见决策 4` / `按决策 3` | 工程档 |
| `relative_heading` | `见文末「后续修订（第 7 步）」`、`见背景四条`、`本文「后果」一节` | 工程档 |
| `document_level` | 整篇引用（`（ADR-0025）`、`以《X》为准`、`见附件`） | 三档都有 |
| `relative_pointer` | `见下` | 工程档 |
| `range_reference` | `决策 1–6` | 工程档 |
| `superseded` / `deprecated` / `deprecated_context` | 已取代 / 已废止 / 已作废语境 | 三档都有 |
| `syntax_example` | 格式示例 | 工程档 |
| `title_clause` / `policy_clause` / `same_doc_clause` / `bare_clause` | `第 N 条`（带/不带限定语） | 政策档、纪要档 |
| `chapter_section` | `第三章第二节` | 政策档 |
| `anchor_section_title` | `[文字](#第二节-退款流程)` | 政策档 |
| `fullwidth_section` / `fullwidth_clause` | 全角数字 | 政策档 |
| `english_section` | `See Section 2.4` | 政策档 |
| `pronoun` | 指代型 | 纪要档 |

## 四、三档语料从哪来，能外推到哪

| 档 | 来源 | 可外推性 |
| --- | --- | --- |
| 工程文档（真） | 本仓库 `docs/adr/0027`、`0028`、`0013`（**真实、非为测试编写**）；目录里另有 41 篇真实文档只作解析目标 | **可外推**到「带链接、带编号、互相引用决策条目的技术文档」（ADR / RFC / 设计文档库）。**不可**外推到 PDF/Word 上传件与无编号体系的白板笔记 |
| 政策散文（合成） | 自拟 5 篇：会员服务协议（章-节）、权益与积分细则（条）、优惠券规则（条）、SLA（节）、英文附件（Section） | **不可外推**（自拟）。只用于**暴露缺口**：条/款、以…为准、见附件、全角数字、`See Section`、章-节双层 |
| 会议纪要（合成） | 自拟 2 篇：产品周会、发布评审，满篇「见上周那份」「按上次说的」 | **不可外推**（自拟）。只用于证明「指代型引用正则做不好」，以及「纪要不是不能建边，是绝大部分写法没有可解析定位符」 |

工程档为什么只标 3 篇：**测量单位是「被完整标注的源文档」**，没标完的文档不能进分母（否则
precision 会把「我没标注」算成「抽取器错了」）。3 篇覆盖了本步相关的整个决策簇，且不是按
抽取器表现挑的——它们是按主题（图谱 / 内核 / 折叠）整取的。

## 五、怎么跑、怎么验

```bash
uv run python scripts/eval_graph_labels.py            # 打印报告
uv run python scripts/eval_graph_labels.py --write    # 同时覆写 eval/graph-labels/report.md
uv run --frozen pytest -q tests/test_graph_labels.py  # 标注集与测量口径的用例
```

用例守三件事，都在 `tests/test_graph_labels.py`：

1. **标注集自身成立**：每条 `evidence` 在源文档里落在**唯一一个节**里；每条 `explicit` 的目标节
   在目录里**恰好一处**；标签与形态取值都在枚举内；`explicit` 必须有 target，其余三类必须没有。
2. **口径不被悄悄改**：`decide()` 的阈值就是票面的 0.7 / 0.95 且两个条件必须同时成立；
   `pooled()` 按边数加权而不是三个比率的平均；分母为 0 时 precision 是 `None` 而不是 0。
3. **报告不漂移**：`report.md` 与当前标注集、当前抽取器一致（重跑一遍逐字相等）。

## 六、已知限制（读报告时必须带着看）

1. **切片边界**：一条引用表达若正好被切片切成两半，抽取器与标注都看不见它。本测量集要求每条
   证据落在唯一一个节里，因此**不含**这类样本；它们的漏检与抽取规则无关，也没被计入 recall。
2. **标题 = 首个 `#` 标题**：生产里标题来自 `documents.title`（上传时落的），Markdown 上传件
   就是它的 h1。`《标题》第 N 节` 对的是标题而不是文件名；若某次上传把标题改成别的，这一档的
   `title_section` 命中会变。
3. **合成两档不可外推**：它们的作用是**暴露缺口**，不是估计真实分布。政策档的 recall 0.0588
   不能读成「政策文档只有 6% 能被抽出来」，只能读成「这几类写法在这份抽取器里一条都走不通」。
4. **工程档的具体数字样本量小**（18 条 `explicit`、3 条边）：分档 precision 的置信区间很宽。
   结论依赖的不是那两个小数，而是**形态表**：真实工程文档里 16/18 条 `explicit` 的定位符是
   「决策序号 / 节标题 / 相对位置」，不是「第 N 节」——这一条不依赖样本量。
