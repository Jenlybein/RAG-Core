## 二、三个问题

### 2.1 文本级缺口闸够不够用？

- 有缺口的题：**10** 题；对齐度分布见上表（对齐 8 / 欠声明 2 / 过声明 0）。
- **判断：文本级基本够用，但有边界**。欠声明占 20.0%（2/10）：不是零，但也没到「多数题被放行」的地步。
- 读法：闸能挡住「完全不认账」的那一类，挡不住「只认一部分」的那一类。后者要不要修取决于调用方怎么用 `coverage.gaps`——它逐要点给出了缺口清单，是文本级闸门的**旁路**。维持文本级的前提是「调用方真的会读 gaps」，这件事这份评测**没有测**。

### 2.2 拦截率是多少？

- 拦截率 **0.0%**（0/10）：`answer_rejected_reason == REJECTED_GAP_NOT_DECLARED` 的题数 / 有缺口的题数。
- 缺口题的落点：声明了 8 题、被闸拦下 0 题、被四条硬校验或生成失败挡下 2 题。
  - A 组：10 题有缺口，其中声明 8、拦截 0、其它拒绝 2
- 拦截率为 0 的两种解释，**用两组的对照分开**：
  - 「提示词约束住了模型」：A 组（半可答，最容易圆场）10 题有缺口，声明了 8 题；B 组（全不可答）0 题有缺口，声明了 0 题。如果连**半可答**那一组都没有一次不认账，那是提示词在起作用，不是题太简单；如果只有 B 组老实、A 组圆场，那说明闸的价值恰恰落在半可答那一侧。
  - 「分母太小」：分母是 **10** 题。它不算小到看不出问题（缺口率本身很高），但也**不足以给出一个稳定的百分比**——一题翻转就是好几个百分点。
- 还有一条结构性的读法：有缺口时答案要么非空且必含「材料不足」（闸放行），要么整份为 `null`（闸或硬校验拦下）。**没有第三种可能**，所以这道闸的失败方式只能是「整份作废」，而不是「放行一句假话」。0 拦截率因此说的是「模型都认了账」，不是「闸没在工作」。

### 2.3 ⑤ 触发率的直接测量值

- 直接测量值：**80.0%**（8/10），判据是 `model_calls >= 4`（= 补证捞到材料、复查真的跑过）。
- 归档反推的参照值：**37.5%**（3/8，取自 `eval/reports/c6/runs/04-v2-research-on/results.json` 的 `stop_reason == max_rounds`）。
  - 那份产物这次也读了一遍：8 题、`max_rounds` 3 题（37.5%），与 #165 报告里的数一致。
- **对照：偏高**（差 +42.5%）。这批题比归档那 8 题更容易触发补证——因为每一题都带一块语料里没有的方面，判定几乎必然报出缺口，而补证几乎必然捞回**别的节**（检索永远返回 top-k）。于是「补证捞到材料」接近必然而非偶然，这抬高了触发率。这说明 37.5% 那类反推对**自然问题**是合适的，对**故意造缺口的题**会低估。

## 五、这份对照不能回答什么

- **样本量 20**：五个率的分母都在 4–20 之间，一题翻转就是 5–25 个百分点。这里够判断「有没有系统性偏差」，不够做版本间比较，也不够给出精确的发生率。
- **半可答题是我方构造的**：10 道 A 组题的「不可答方面」由我们追加，追加串接在原题后面。构造带来了两处偏差：(1) 追加的方面偏向「一个拎得出来的名词」（数字人民币、区块链、企业微信），而真实用户的问题里缺口往往是**半个概念**；(2) 追加串很短，规划器有时会把它并进相邻要点，于是「这道题有几个缺口」并不完全由我们决定。
- **A 组追加的方面可能被规划器拆成与预期不同的要点**：我们只保证「那一块在语料里没有」，不保证模型把它单独拆成一条要点——它可能被并进别的要点、也可能被拆成两条。所以「欠声明」里有一部分其实是「缺口数被拆多了」，看逐题明细的要点文本可以人工复核。
- **只测一个模型链**：规划 / 判定 / 复查 / 生成走的是 `fast` 与 `strong` 两个角色指针，这次落在同一个供应商的同一条模型上（见报告头部的链路）。换模型、换思考强度，读数会变；这里没有做模型间对照。
- **`plan` 的检索会被降级改写**：一旦关键词一路失败，`sub_search_degraded` 会记一条，本次读数就变成「向量单路下的闸门行为」。逐题记录里带了这个字段，请连同它一起读。
- **「不可答」的机械证据只覆盖关键词这一种形态**：关键词 0 命中证明「这个词不在库里」，不证明「这块知识不在库里」——库里可能用别的说法写了。反向偏差是存在的（把可答的当成了不可答），它会让缺口出现率偏高。B 组里 6 题取自题库 `absent` 标注（问题侧、写在检索之前），那 6 题的证据更强；我方构造的 4 题只有关键词证据。
- **不测答案对不对**：本票只量闸门行为（缺口报没报、声明对不齐、拦没拦），不评答案质量。「声明了材料不足」不代表那一块真的不足，也不代表其余部分答对了。
- **一次跑批**：没有重复跑，所以没有跑间方差；模型的抽样波动会让这次的分布挪位。

跑的是**生产完整链路**：`run_research`（规划 → 并行检索 → 覆盖判定 → 定向补证 → 复查 → 生成）+ 生产检索内核 `build_kernel_search` + 两个真实模型角色。没有构造材料池，也没有另写一套提示词——这是本票与 #165 的关键区别。
