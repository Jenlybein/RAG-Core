## 二、三个问题

### 2.1 文本级缺口闸够不够用？

- 有缺口的题 **20** 题，其中**真的交出了答案**的 **17** 题是对齐度的分母；另外 3 题答案被整份作废（被四条硬校验 / 生成失败挡下），未测量——它们是：A02（`malformed answer output`）、A08（`unresolved evidence reference`）、B01（`unresolved evidence reference`）。
- 对齐度分布：对齐 **17** / 欠声明 **0** / 过声明 **0**（分布表见上；分母 17）。
- **判断：文本级够用**。欠声明 0/17（0 例）：每一道真的交了答案的缺口题，声明块数都**正好等于**缺口数（对齐 17/17，过声明 0/17）——闸没有漏掉任何「假装没有缺口」的答案，也没有出现「有缺口却只写一句」的情形。
- 于是 ADR-0029 实施备注第 4 条可以从「推测够用」改成「实测够用」——**在这 17 道真的生成了答案的题上、这一个模型链上**。翻案条件不变：只要出现「3 个缺口只写 1 句」这类样本，就该重新裁决。
- 但要读清楚**为什么对齐**：提示词对每个缺口要点都点名要求「各写一块 `insufficient`」，模型照做了；闸本身仍然只数那句话在不在。也就是说，**对齐度是靠提示词得到的，闸只是兜底**——这一条正是「维持文本级」的代价：把可靠性押在模型听话上，而不是押在结构上。

### 2.2 拦截率是多少？

- 拦截率 **0.0%**（0/20）：`answer_rejected_reason == REJECTED_GAP_NOT_DECLARED` 的题数 / 有缺口的题数。
- 缺口题的落点：声明了 17 题、被闸拦下 0 题、被四条硬校验或生成失败挡下 3 题。
  - A 组：10 题有缺口，其中声明 8、拦截 0、其它拒绝 2
  - B 组：10 题有缺口，其中声明 9、拦截 0、其它拒绝 1
- 拦截率为 0 的两种解释，**用两组的对照分开**：
  - **「提示词约束住了模型」——数据支持这一条**：A 组（半可答，最容易圆场）10 题有缺口，声明了 8 题，**0 题不认账**；B 组（全不可答）10 题有缺口，声明了 9 题，同样 0 题不认账。两组的落点几乎一样，也就是说连最该圆场的那一组也没圆场——这是提示词在起作用，不是题太简单。顺带说：本票原本假设「半可答最容易被顺手答完」，**这批题里没有出现**。
  - **「分母太小」——这一条只部分成立**：分母是 **20** 题，一题翻转就是 5 个百分点，给不出稳定的百分比；但它的方向是确定的——3 次失败全是**答案被别的原因整份作废**（A02（`malformed answer output`）、A08（`unresolved evidence reference`）、B01（`unresolved evidence reference`）），**没有一次是「闸门该拦而没拦」**。
- 还有一条结构性的读法：有缺口时答案要么非空且必含「材料不足」（闸放行），要么整份为 `null`（闸或硬校验拦下）。**没有第三种可能**，所以这道闸的失败方式只能是「整份作废」，而不是「放行一句假话」。0 拦截率因此说的是「模型都认了账」，不是「闸没在工作」。反过来说，**这道闸在这批题上一次也没被真正挑战过**：它没有失败，也没有立功——真正挡住「假装没缺口」的是提示词。

### 3.4 两种价值：暴露 vs 救回（**分开报，不合成改善率**）

- 逐要点比了 **10** 题；关 ⑤ 时落 `unknown` 的要点 **13** 条，其中开 ⑤ 之后：**`unknown → none` 13** 条（`100.0%`）、**`unknown → supported` 0** 条（`0.0%`）、仍是 `unknown` 0 条（复查失败）。
- **判断：⑤ 的价值主要落在「暴露」而不是「救回」**（13 对 0）。它把一批其实没有支撑的要点从 `unknown` 落成 `none`，于是缺口清单变长、答案被要求声明得更多。**这不是「提高覆盖率」，是「让隐藏缺口现形」**——两件事对产品的含义不同：前者让答案变多，后者让答案变少但更准。
- 顺带的推论：关掉 ⑤ 时那些要点**既不算缺口也不算支撑**，缺口闸看不见它们（文本级，只认 `gaps`），生成步却拿着那条材料照答。这正是 ⑤ 存在的理由。

## 六、这份对照不能回答什么

- **样本量 20**：五个率的分母都在 4–20 之间，一题翻转就是 5–25 个百分点。这里够判断「有没有系统性偏差」，不够做版本间比较，也不够给出精确的发生率。
- **半可答题是我方构造的**：10 道 A 组题的「不可答方面」由我们追加，追加串接在原题后面。构造带来了两处偏差：(1) 追加的方面偏向「一个拎得出来的名词」（数字人民币、区块链、企业微信），而真实用户的问题里缺口往往是**半个概念**；(2) 追加串很短，规划器有时会把它并进相邻要点，于是「这道题有几个缺口」并不完全由我们决定。
- **A 组追加的方面可能被规划器拆成与预期不同的要点**：我们只保证「那一块在语料里没有」，不保证模型把它单独拆成一条要点——它可能被并进别的要点、也可能被拆成两条。所以「欠声明」里有一部分其实是「缺口数被拆多了」，看逐题明细的要点文本可以人工复核。
- **只测一个模型链**：规划 / 判定 / 复查 / 生成走的是 `fast` 与 `strong` 两个角色指针，这次落在同一个供应商的同一条模型上（见报告头部的链路）。换模型、换思考强度，读数会变；这里没有做模型间对照。
- **`plan` 的检索会被降级改写**：一旦关键词或向量一路失败，`sub_search_degraded` 会记一条，本次读数就变成「单路检索下的闸门行为」。这次降级过的题：A06、A08、A10。逐题记录里带了这个字段，请连同它一起读。
- **「不可答」的机械证据只覆盖关键词这一种形态**：关键词 0 命中证明「这个词不在库里」，不证明「这块知识不在库里」——库里可能用别的说法写了。反向偏差是存在的（把可答的当成了不可答），它会让缺口出现率偏高。B 组里 6 题取自题库 `absent` 标注（问题侧、写在检索之前），那 6 题的证据更强；我方构造的 4 题只有关键词证据。
- **不测答案对不对**：本票只量闸门行为（缺口报没报、声明对不齐、拦没拦），不评答案质量。「声明了材料不足」不代表那一块真的不足，也不代表其余部分答对了。
- **一次跑批**：没有重复跑，所以没有跑间方差；模型的抽样波动会让这次的分布挪位。第三节那份对照尤其要吃这一条：条件 1 与条件 2 是**两次独立跑**，规划与判定都是新的样本，所以「gaps 变多/变少」里既有 ⑤ 的效果，也有抽样噪声。
- **⑤ 的对照按关键词对齐**：两次跑的规划从来不一样（这次 **10/10 题**的要点清单都变了），所以「哪条要点说的是同一件事」只能靠**我们注入并机械验证过的关键词**判断，而不是序号或措辞。与不可答方面无关的 `unknown`、以及开 ⑤ 那次没规划出来的方面，都单列、不计入改判分布——于是改判的那几个数**分母偏小**，不能当成「⑤ 的总体改判率」。
- **关 ⑤ 是一个不存在的生产配置**：真实部署里 ⑤ 总是开着。条件 2 是**反事实**测量，用来回答「若没有它会怎样」，不代表任何可运行的版本。
- **`unknown → supported` 被题集结构性地压低了**：我们每题的缺口方面**在语料里根本不存在**（0 命中的机械证据就是它），所以补证捞回来的材料几乎不可能真的撑住那个方面，复查自然落成 `none`。真实场景里缺口常常是「这部分材料没召回」而不是「库里没有」，那种情况下「救回」的比例会高得多——**这次 0 条救回不能被读成「⑤ 从不救回」**。
- **3 题答案被别的原因整份作废**（`malformed answer output`：生成阶段强模型超时；`unresolved evidence reference`：块里引到了不该出现的编号）。它们没有进入对齐度的分母，也没有进入拦截率——这 3 题的「有缺口却不认账」到底会不会发生，这次没测到。

## 七、怎么复现

```powershell

uv run python scripts/eval_t167_gap_gate.py plan

# 全量（名义 110 次、最坏 140 次模型调用）
uv run python scripts/eval_t167_gap_gate.py run

# 按当前口径重算指标并重出报告（0 次模型调用）

```

跑的是**生产完整链路**：`run_research`（规划 → 并行检索 → 覆盖判定 → 定向补证 → 复查 → 生成）+ 生产检索内核 `build_kernel_search` + 两个真实模型角色。没有构造材料池，也没有另写一套提示词——这是本票与 #165 的关键区别。
